## 3. Questions

### Section A: Multiple Choice (10 x 1 = 10 marks)

**Q1.** In the Waterfall model, a phase can begin only when:
a) The customer approves the budget
b) The previous phase is completed
c) Testing is finished
d) The code is deployed

**Q2.** Which process model is driven mainly by risk analysis?
a) Waterfall b) Spiral c) Prototype d) Big Bang

**Q3.** "The system shall allow a student to register for a course" is an example of a:
a) Non-functional requirement
b) Functional requirement
c) Design constraint
d) Test case

**Q4.** The formal document that records all software requirements is called:
a) SRS b) SDD c) UML d) RTM

**Q5.** A good software design should have:
a) High coupling, low cohesion
b) High coupling, high cohesion
c) Low coupling, high cohesion
d) Low coupling, low cohesion

**Q6.** Which UML diagram shows the static structure of a system (classes and relationships)?
a) Sequence diagram b) Use case diagram c) Class diagram d) Activity diagram

**Q7.** Testing of individual modules or functions in isolation is called:
a) Unit testing b) Integration testing c) System testing d) Acceptance testing

**Q8.** Black-box testing is based on:
a) Internal code structure
b) Specifications, without knowing internal code
c) Database schema
d) Compiler output

**Q9.** Which type of maintenance is performed to fix bugs found after delivery?
a) Corrective b) Adaptive c) Perfective d) Preventive

**Q10.** COCOMO is a technique used for:
a) Software testing
b) Software design
c) Software cost estimation
d) Requirement elicitation

### Section B: Short Answer (5 x 4 = 20 marks)

**Q11.** Explain two differences between the Waterfall model and the Agile model. (4)

**Q12.** Differentiate between functional and non-functional requirements. Give one example of each. (4)

**Q13.** Explain the terms *coupling* and *cohesion*. Why does good design aim for low coupling and high cohesion? (4)

**Q14.** Describe the difference between *verification* and *validation* with one example each. (4)

**Q15.** Briefly explain the four types of software maintenance. (4)

### Section C: Descriptive (2 x 5 = 10 marks)

**Q16.** Explain the three-tier (layered) architecture with a labelled diagram. Describe the role of each layer. (5)

**Q17.** Describe the main activities (phases) of the Software Development Life Cycle (SDLC). Explain the purpose of each phase. (5)

## 5. Answer Key and Marking Scheme

**Section A:** Q1-b, Q2-b, Q3-b, Q4-a, Q5-c, Q6-c, Q7-a, Q8-b, Q9-a, Q10-c

**Section B (4 marks each):**
- Q11: 2 correct differences x 2 marks (e.g., sequential vs iterative; fixed vs changing requirements; late vs early customer feedback).
- Q12: definition of each (1 + 1), correct example of each (1 + 1).
- Q13: coupling explained (1), cohesion explained (1), reason: easier maintenance, reuse and testing (2).
- Q14: verification = "are we building the product right" (1) with example (1); validation = "are we building the right product" (1) with example (1).
- Q15: corrective, adaptive, perfective, preventive, 1 mark each with a one-line explanation.

**Section C (5 marks each):**
- Q16: correct diagram with Presentation, Business Logic, Data layers (2); role of each layer (3).
- Q17: five or more phases (planning, requirements, design, implementation, testing, deployment, maintenance) listed (2); purpose of each explained (3).
